# 画面与识别校准

## 支持的输入基线

当前识别基线是 Switch 2 的 1920×1080、中文界面、30 fps UVC 采集画面。后端会按设备名称和硬件 ID 重新解析采集设备，避免把易漂移的 OpenCV 数值索引当成永久标识。

前端不再提供地图框拖动或画面锚点录制。四张地图区域由 `vision_service/backend.py` 的实测归一化坐标统一管理；后端收到旧前端保存的地图框时会忽略它们，并在配置迁移后写回当前结构。这样审计截图、在线评分和历史重算始终使用同一裁切合同。

更换游戏语言、输出分辨率、采集卡缩放方式或游戏页面布局后，不应临时在前端拉框规避问题。应更新后端坐标和对应的稳定帧/裁切回归测试，然后执行 `npm run check`。

## 页面识别

状态机直接分析原始采集帧，区分无信号、加载、名字键盘、生日选择、人物样式、外貌编辑、选择对话、四岛地图、普通对话和启动提示。识别不足时保留现场，不以固定延时猜测页面。

### 中文姓名

- 用户为每个汉字提供一项无声调拼音。
- 程序输入当前拼音后，以高频 OCR 检查候选栏。
- 候选栏若呈现词语布局而不是单字插槽，流程停止，不继续猜测。
- 目标字必须在连续结果中落在同一候选位置并满足置信度门禁，之后才发送选择输入。
- 一字完成后清理输入并重新识别下一字，最终姓名仍须由状态机确认页面切换。

### 生日与人物页面

生日路径根据配置中的初始月、日计算环形最短移动，不把某个测试生日写死在流程中。人物样式和默认外貌只有在对应页面识别可靠后才提交。若提交后页面没有切换，系统按递增等待间隔执行最多三轮页面确认重试；仍未切换就停止并释放输入。

## 四岛页稳定门禁

四岛页出现不等于地图已经可分析。后端同时检查：

- 四个固定地图区域的色彩渲染完整度至少为 `78%`；
- 首次发现地图页后至少等待 `0.65 s`；
- 相邻地图签名的平均变化量不高于 `0.012`；
- 连续满足稳定条件两次。

淡入叠帧、标题残影或地图仍在变化时只更新“等待稳定”的状态，不创建审计、不累计命中帧，也不对候选作保留/放弃判断。

## 地图规则

地图评分只由 Python/OpenCV 后端计算。六项规则均为硬条件：

1. 左右海岸完整大礁石；
2. 机场与广场位置关系：机场出口和广场各自距地图中线不超过 `5%`，两者横向错位不超过 `2%`；
3. 指定宽浮岛结构；
4. 北侧狐狸海滩位置；
5. 沙岸圆润度；
6. 两个入海口且非双南。

“指定宽浮岛结构”只接受用户确认的左右镜像宽头结构。后端在固定的 `192×144` 分析坐标内同时检查向海外伸深度、结构高度、轮廓填充率与两端平衡度：外伸不足的小型岸角、沿海方向过高的条形结构、尖角及破碎轮廓都会作为硬条件失败。该判断固定在 OpenCV 后端，前端既不提供裁切框，也不参与规则计算。

辅助目标图只提供低权重视觉相似度，不替代硬条件，也不要求内部河流或高地逐像素相同。

## 阈值与连续帧

默认综合阈值为 `76%`，默认连续命中三帧。综合阈值只在所有硬条件都通过之后生效：

- 同一地图低于阈值：先查看具体因素与识别置信度，而不是直接降低门槛；
- 分数快速跳变：检查 UVC 帧是否稳定、是否存在缩放/转场或采集丢帧；
- 明显错误的因素：保留该轮审计，使用固定裁切原图补充后端回归测试；
- 算法修改后：运行 `npm run vision:reanalyze-audits` 比较历史证据，再进行实机演练。

命中后系统只移动到目标卡片并进入等待用户决定状态，不会自动确认地图。

## 推荐验收顺序

1. 确认设备页显示正确的 UVC 名称、ID 和 1920×1080 输入。
2. 在演练模式完成姓名、生日、人物页面与一轮四岛识别。
3. 检查四张审计裁切图均完整包含地图，且没有转场重影。
4. 用至少一组应通过和一组应拒绝的审计验证规则。
5. 执行 `npm run check`。
6. 确认控制器已连接且能全释放，最后才关闭演练模式。
